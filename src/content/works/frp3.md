# 让 frp 配置更简单：用 frpc-editor 可视化创建和管理内网穿透

想让别人访问本地开发的网站，或者从外面连接自己的内网服务，很多人会用到 frp。但真正开始配置时，又经常卡在同一件事上：打开 `frpc.toml`，对照示例找参数，修改地址和端口，再回到命令行启动程序。

一条映射还能应付，规则多起来之后，反复查配置、改文件、切窗口就变成了日常负担。

**frpc-editor 把这些操作集中到了一个桌面应用里，让你通过可视化表单方便地创建、修改和运行 frpc 配置。** 对于刚接触 frp 的用户，它提供了更直观的入口；对于已经在使用 frp 的开发者和运维人员，它让日常配置维护更顺手。

## 从填写表单开始，创建第一条代理映射

使用 frpc-editor，不必从空白配置文件开始。

在“全局配置”中填写服务端地址和端口，在“认证配置”中设置连接所需的认证信息，然后进入“代理映射”，添加需要转发的本地服务。

例如，你有一个运行在本机 `3000` 端口的 Web 项目，希望通过 frp 服务端的 `18080` 端口提供临时演示。在服务端允许使用该端口的前提下，可以创建这样一条 TCP 映射：

| 配置项 | 示例值 | 含义 |
| --- | --- | --- |
| 代理名称 | `web-demo` | 为这条规则起一个容易辨认的名字 |
| 代理类型 | `TCP` | 使用 TCP 转发 |
| 本地地址 | `127.0.0.1` | 服务运行在 frpc 所在电脑上 |
| 本地端口 | `3000` | 本地 Web 项目的监听端口 |
| 远程端口 | `18080` | frp 服务端对外提供访问的端口 |

这样，原本需要在文本中查找和修改的参数，就变成了几个明确的输入项。完成配置并建立连接后，在网络和端口放行条件满足的情况下，就可以通过服务端地址和远程端口访问该服务。

对于需要临时展示开发成果、联调接口，或者维护几条固定映射的用户，这种方式更容易看清自己配置了什么。

## 表单负责易用，TOML 预览保留透明度

图形化工具的便利，不应以看不到实际配置为代价。

frpc-editor 提供实时 TOML 预览。修改表单后，可以直接查看生成的 `frpc.toml` 内容，也可以复制或导出配置文件。页面还提供配置校验提示，帮助发现部分填写问题。

这对新手尤其有帮助：一边填写字段，一边观察配置文件如何变化，比单独阅读一大段参数说明更直观。熟悉 frp 的用户也可以在启动前检查生成结果，确认关键参数符合预期。

应用同时提供 TOML 导入入口，方便把已有配置带入表单继续整理。对于使用较新版本参数或特殊扩展字段的配置，导入后应核对生成内容，确认所需字段得到保留。

## 多条规则，放在同一个界面里维护

当使用场景从一个本地网站扩展到多个服务时，配置管理的重要性就会显现出来。

frpc-editor 提供代理映射列表，并支持 TCP、UDP、HTTP、HTTPS、STCP、SUDP、XTCP、TCPMUX 等代理类型的配置入口，还提供 STCP、XTCP 访问端配置。

你可以根据实际需求，为不同服务建立独立规则，再通过界面逐条查看和修改。除了代理本身，全局、认证、传输、Web 管理、日志和 Includes 等配置也有对应页面。

对于刚开始使用的人，可以先完成基础连接和一条映射；需要进一步调整时，再进入相应页面设置。配置项有了明确的位置，后续维护也更容易找到入口。

## 配好之后，直接在应用里启动

配置文件准备好，接下来就是运行 frpc。

在“frpc 管理”页面选择本地 `frpc.exe` 和配置文件路径，就可以通过按钮启动或停止 frpc。页面提供进程运行状态、PID，以及启动和停止等操作记录，方便确认应用管理的进程是否在运行。

日常使用时，还可以通过系统托盘显示窗口、启动或停止 frpc。当 frpc 正在运行时，关闭主窗口会隐藏到托盘，减少桌面占用。

需要区分的是，**进程正在运行代表客户端程序已启动，实际服务能否访问还取决于服务端连接、代理配置和网络条件。** 首次配置后，实际访问一次目标服务，才算走完完整的使用流程。

## 为经常使用的人，减少重复操作

如果你每天都要使用相同的映射，便利性还体现在这些细节里：

- **自动保存配置**：修改后自动保存到当前配置文件，并显示保存状态。
- **登录后自动启动应用**：通过开机启动设置，让工具随系统登录启动。
- **可选自动启动 frpc**：提前保存有效的程序和配置路径后，可让应用在开机启动时运行 frpc。
- **深色与浅色主题**：根据自己的桌面环境和阅读习惯切换外观。

这些功能让一次性的配置操作，更容易延续为日常使用习惯。

## 谁适合试试 frpc-editor？

**刚接触 frp 的用户**，可以从表单开始理解服务器、端口和代理映射，减少对 TOML 语法和启动命令的依赖。

**经常做本地演示和接口联调的开发者**，可以把常用映射整理到应用中，需要调整时直接打开对应规则。

**维护内网服务的运维人员和家庭实验室用户**，可以集中编辑常用配置，通过桌面界面和托盘完成客户端进程操作。

如果你已经熟悉手写配置，但希望少一些文件编辑器与命令行之间的切换，frpc-editor 同样值得尝试。

## 开始使用前，需要准备什么？

frpc-editor 是 frpc 的配置与进程管理工具。使用前，需要准备可连接的 frp 服务端信息，以及适合本机系统的 frpc 可执行文件；应用不会代替你提供公网服务器，也不内置 frpc 客户端。

以 Windows 为例，基本流程如下：

1. 从项目的 Releases 页面查看可用版本，获取桌面应用，并准备本地 `frpc.exe`。
2. 填写服务端地址、端口和认证信息。
3. 在“代理映射”中创建一条规则。
4. 在“TOML 预览”中检查生成的配置，确认保存状态。
5. 在“frpc 管理”中选择程序与配置文件，点击启动，再实际测试目标服务的访问。

完整的文件保存、进程管理和开机启动功能，需要在桌面应用中使用。

## 把时间留给服务本身

frpc-editor 的价值，体现在每一次具体操作里：新增映射时有表单，检查参数时有预览，运行客户端时有按钮，日常使用时有托盘和启动设置。

如果你也希望更方便地创建和维护 frpc 配置，可以从一条常用映射开始，体验这套桌面工作流程。
